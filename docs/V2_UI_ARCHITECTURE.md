# V2 UI architecture

`NetStuck.UiV2.cs` owns the new presentation layer: design dimensions, application shell, sidebar navigation, page descriptions, Home/Settings, Ping composition, responsive toolbar, detail presentation and native accessibility metadata. It is the tenth explicit production source in `NetStuck.BuildProvenance.ps1`.

The existing active page builders still create their controls, DataTables, BindingSources and handlers. V2 recomposes Ping's controls once before theme binding/state restoration; it does not build views during polling or resize. Networking remains in the established partial MainForm layers. UI callbacks continue to use the existing Ping/Collector queues and Traceroute lifecycle ownership.

The shell is one table with an absolute logical sidebar and a flexible workspace. Each workspace has one shared header and a native page host. `WorkspaceTabs` preserves native page ownership, keyboard traversal and old persisted indices while its tab headers are hidden. Native sidebar buttons select pages by stable dictionary IDs; Ctrl+Shift+U reaches version recovery. Activity indicators include text and an accessible description.

Ping contains a resizable fixed-first-panel split. Its left column has separate target and probe surfaces in a scroller with pinned operation actions. Its right column divides results from history. The full result toolbar is shown when space permits; More retains Columns, summary visibility and Clear in a compact viewport. The optional history detail pane collapses below 900 logical pixels; Details still opens the selected text in an owner-centered dialog. Existing filter/copy/export/selection semantics are unchanged.

Other workflows keep their established input groupings, especially the three-row Traceroute controls and two sessions. Shared headers, theme resources, action styling, responsive page wrappers and navigation give them the same shell. Collector's configuration split reserves adequate credential width; collection/stop actions remain outside its input scroller. Calculators and Event Log retain their Phase A accessible field ordering, state presenters and announcements.

Scaling remains a 96-DPI design baseline with WinForms DPI autoscaling and the existing system-aware manifest. Runtime viewport/splitter/working-area calculations start from logical constants through `LayoutPixels`; they do not repeatedly scale already-scaled bounds. Fixed first panes retain logical width after resize; free splitters preserve their ratio. The nominal 1100×700 minimum is scaled and capped to the current working area. Move, resize, display-change and state-restoration paths keep the main window on an available monitor. The page/input scrollers are the constrained-workspace fallback.

Windows High Contrast uses system colors; user-preference changes reapply the existing palette. Navigation icon colors follow their text color. Native control roles/focus are retained; privately owned icon/font resources and the preference event subscription are released on disposal. The application does not opt into .NET Framework 4.7 PerMonitorV2 or add a config file. That would require a separately validated runtime and deployment change; see [Microsoft's Framework DPI guidance](https://learn.microsoft.com/en-us/dotnet/desktop/winforms/high-dpi-support-in-windows-forms).

Version replacement remains in `NetStuck.Updates.cs`. Latest checks only offer newer stable releases. Historical discovery lists compatible older packages, including v1.3.1 archived on v1.3.3. The exact selected executable version is verified independently of the archive's release tag. An explicit downgrade job records mode and expected installed identity. The helper revalidates both before copying, retains a durable application-file backup and uses the existing rollback/restart path. State, captures and unrelated portable files are outside its replacement inventory.
