NetStuck v.1.2.3 - Baseline Verification Report
======================================

Build target: Windows .NET Framework 4.x, AnyCPU, optimized WinExe
Assembly/File version: 1.2.3.0
Verification date: 2026-08-26

Final result
------------

- Core tests: 16/16 passed
- Feature, UI and integration tests: 91/91 passed
- Performance tests: 10/10 passed
- Fixed-cadence tests: 3/3 passed
- Accelerated soak checks: 8/8 passed
- Total automated checks: 128/128 passed
- Build: passed with no compiler errors

Validated changes
-----------------

- Traceroute inputs use adjacent deterministic grid columns and never overlap.
- Protocol, Port and Packet Size share the lower input row, leaving no timing
  input below the Protocol dropdown.
- Traceroute actions use a dedicated row and do not intersect input fields.
- Enabled and disabled Traceroute inputs retain the same white background.
- The Traceroute split remains usable at the 1100-pixel minimum window width.
- Constrained-desktop startup preserves usable Traceroute and Collector input panes.
- Collector error CSV contains only IP, Status, Protocol, Username and Detail,
  and excludes completed rows and credentials.
- Large SSH output above 2 MB streams to disk while the in-memory preview stays
  below 550 KB and memory growth stays below 100 MB.
- Collector terminal batches 1,000 messages into fewer than 40 UI flushes.
- Traceroute fields have complete borders and equal Protocol/Port/Packet widths.
- Traceroute stable cycles reduce TTL probes while retaining the destination.
- Traceroute updates preserve vertical/horizontal scroll and current-cell state.
- ISP and DNS cache data survives reload with timestamp/TTL metadata.
- Log Sanitizer implementation and legacy state fields are absent from source.
- DOMAIN\username, prompt-aware SSH, AUTH fallback and Telnet integration remain
  covered by end-to-end tests.
- UTF-8 console regression coverage confirms Collector stdin is BOM-free while
  passwords remain absent from process arguments.
- Shared grid resources remain valid through native control teardown, preventing
  the intermittent access fault previously seen after cadence tests completed.
- Startup NTP/Public-IP continuations stop touching controls during shutdown;
  deterministic test state disables those external calls during UI timing suites.
- Accelerated soak covers packet loss, route/DNS changes, TACACS rejection,
  VTY/session limits, terminal pressure, memory and UI responsiveness.
